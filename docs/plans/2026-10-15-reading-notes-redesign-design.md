# 阅读体验重构 · 总体方案（讨论稿）

> 2026-10-15 讨论定稿。状态：**设计已对齐，未进入落地**。实现启动前按「阶段划分」逐段验收。
> 本稿为讨论产物，未随发版流程走；与代码现状冲突处以本稿为准，落地时再更新本稿。

## 1. 背景与目标

现状两个方向——「专题化研究」（专题=工作台：中栏检索+单条阅读+笔记+AI）与「文档阅读」（文档库→全页阅读/书籍阅读）——并行，但用户实际以文档阅读为主，专题里的法条搜索与阅读不便。本次重构目标：

- **以「读」和「写」为主体**：阅读体验（聚焦文档 + 侧栏速记/截图）与笔记体系（大纲+思维导图）是应用主干；
- **专题整块退场**，其收集/导出职责由笔记吸收；**专题数据不做迁移**（UI 移除，旧表原样保留，不做任何转换）；
- 全应用只剩两个方向：**文档库 / 笔记**。

## 2. 信息架构（总图）

- **文档库**（保留现状）：分类文件夹、卡片、导入。所有阅读落点统一为同一个全页阅读视图。
- **笔记**（新，替代专题）：笔记库（列表+搜索+编辑器）；写笔记时可插入文档库内容；导出 md/docx（承接原专题导出）。
- **横切能力**：
  - 顶栏搜索（保留）：结果**直达全页阅读并跳转到该条**（带高亮）。中栏单条视图随专题退场。
  - **AI 全局助手（2026-10-17 重定位：通用问答）**：顶栏「✦ AI 助手」右侧抽屉，任何界面唤出、**随问随答**——不绑法条/不绑检索，用户不必出 app 去别处查；无材料上下文走通用系统提示词（自身知识作答、拿不准必须明说）；归档 article_id=NULL 入全局时间线（旧按条文记录同线可见）；解读/找案例代码能力保留（带 articleId 才出现，UI 默认不带）。
  - **星标**：轻量临时收集，法条表独立标记；搜索结果/阅读页可点亮，笔记库有星标条目列表入口。不进笔记模型。
- **左导航**：「专题 / 文档库」→「文档库 / 笔记」。

## 3. 笔记模型（核心）

**笔记 = 大纲树**，不是成文文档：

- 一行一个节点，缩进即层级（幕布/Workflowy 本质）；节点文字内嵌：贴图、法条引用（纯内容，**无跳转**）；
- 存储：单表 JSON（节点 id/父/序/文本），百级节点量级足够；全局搜索另建 FTS 档；
- 锚点元数据**取消**——关联全部走笔记内引用，无「笔记挂在文档上」的概念，无反链。

**插入文档库内容**（关联的唯一通道）：

1. 笔记编辑器入口 → 弹出浮层 → 浮层内搜索文档库；
2. 下方搜索建议列表，**每条旁带 ＋ 按钮**；点 ＋ 插入到光标处，浮层不关、可连加多条；
3. 插入形态：引用节点（《法规》第X条 + 标题）+ **条文正文为其子节点**（大纲天然折叠，嫌长删子节点即可）。

**图片**：贴图（Ctrl+V）存本机 `userData/attachments/`，节点内相对路径引用，随数据包备份。

## 3.5 笔记与文档阅读的共存契约（2026-10-17 讨论定稿）

**原则**：读的主场在文档（+批注眉批），写的主场在笔记（大纲成文）；两边之间只有"引用"单向通道。

1. **入口**：左导航两项「文档库 / 笔记」平级切换；不存在并排形态（如需边读边写，将来演进为"单篇笔记独立窗"，不进本期）。
2. **续读契约（用户点名必须做好）**：
   - 离开阅读（切去笔记）时**强制冲刷阅读进度落盘**（防抖未到期也要存——StatuteReadingView/ReadingView 卸载钩子需补 flush）；
   - 从笔记返回文档库：若离开时正在阅读 → **静默重开该文档并恢复位置**（不弹"已回到上次阅读位置"横幅）；若停在库首页 → 回首页；
   - 顶栏搜索直达自动切到文档库方向；返回续读以**最近一次阅读**为准；
   - 期间文档被删 → 落回首页 + 提示，不白屏。
3. **读→写只做「复制引用」**：阅读选区右键 → 复制引用（《法规》第X条+选中原文）→ 粘进笔记成引用节点。「发送到笔记」不做——文档库保持阅读纯粹性，批注已是完整眉批体系。
4. **写→读默认不跳**（已定）；**逃生门**：笔记内引用节点右键 →「在文档库打开来源」（显式动作，单击不跳原则不变）。

## 4. 阅读板块（2026-10-16 重定：本版聚焦法条批注，无右栏）

用户拍板：使用视角只有**法条 / 其他**两类；本版只完善法条，书籍/资料/PDF 保持现状（旧划选批注继续可用，不升级不迁移）。**右速记栏/截图栏从本版移除，降为后续版本按需再议**（批注若覆盖了"旁边放东西"的需求则可能永不上）。

**法条批注（本版核心功能）**：

1. 阅读时**选中条文文字 → 右键** → 菜单出现「添加批注」（扩展现有右键菜单；无选中/输入框场景不受影响）；
2. 弹出**批注浮窗**，就地编辑；
3. 点浮窗外部任意处 → **浮窗自动收起**，批注自动保存；
4. 原选区保留高亮 + 常驻**小星标（★）**标记「此处有批注」；
5. 点星标 → 浮窗重新弹出，查看/继续编辑/删除。

**数据模型**：独立批注表，锚定 = 法条 article_id + 选区字符起止偏移 + 原文引用（复用书籍批注的锚定渲染思路：存引用与偏移、加载时恢复高亮）。永久保存、跟文档走，与笔记库互相独立（笔记库插引用不跳转，见 §3）。

**其余阅读面**：工具条统一化、目录摆位等随批注实施时顺手对稿，不单独立项。

## 5. 大纲编辑器与思维导图

- **大纲视图为编辑本体**（默认）：自研——嵌套列表、Tab/Shift+Tab 缩进、回车新建、拖动排序（沿用仓库既有拖动配方）。锚定/引用内嵌/贴图深度定制是核心，现成 outliner 嵌不进去。
- **导图 = 同一棵树的只读视图**：一键切换（幕布式，快捷键可配），初期只读 + 点击节点定位到大纲行；导图内直接编辑后置。
- 渲染选型：**jsMind**（MIT、小、经典树布局）——新增 npm 运行依赖，**落地安装时按规矩另行报告并须确认**。

## 6. 专题退场（直接切除，老数据删除）

用户拍板（2026-10-15）：**板块直接切掉、老数据删掉**，不留回滚余地，防止冗余代码与数据堆积影响后续开发。

- 代码：专题 Tab、TopicPanel、专题级笔记/AI、专题导出、workspace/exporter 中专题相关路径**整链路删除**（不做兼容层、不留死代码）；
- 数据：迁移一次性 **DROP** topics / topic_items / notes（旧专题笔记）；ai_messages 中按专题归档的记录（topic_id 路径）随删（按条文归档的保留）；
- 导出能力迁到笔记：笔记 → md/docx（大纲降级为嵌套列表；引用节点导出为《法规》第X条+正文）。

## 7. 数据层变更概要

- 新增：`outlines`（笔记大纲树）：id/标题/树 JSON/时间；attachments 文件目录约定（`userData/attachments/`）；
- 法条表：加 `starred` 标记（轻量迁移）；
- 删除（迁移内 DROP）：topics / topic_items / notes（旧专题笔记）；ai_messages 的专题归档路径随之消亡；
- 书籍旧划选批注（book_notes）：阅读视图统一完成前继续可读可用；统一后写路径切新模型，旧表随后续版本随新笔记体系稳定后删除（**不迁移**，届时单独确认一次）；
- FTS：新增笔记文本档（可选，第一批可不做，列表内搜索先 LIKE）。

## 8. 栏宽可调（最终阶段，先审计后实施）

用户要求：各栏大小尽量可调且协调。实施策略：

- **随建随打底**：新造各栏（速记栏/目录条/笔记库两栏/AI 抽屉）时即用 CSS 变量 + min/max 约束写死初始值——零成本、防返工；
- **精细轮次放最后**：先做一轮**审计**（见清单）→ 出「哪些栏、怎么调」的确认稿 → 用户过目 → 再实施；
- 审计清单：① 现存固定宽栏位盘点（文档库两栏、全页阅读正文+目录、速记栏、笔记库列表+编辑区、AI 抽屉、中栏等）；② 各栏 min/max/默认宽建议；③ 交互统一（拖拽把手样式、双击复位、是否记忆宽度——建议存 settings）；④ 窄窗协调规则（自动收起优先级）。

## 9. 阶段划分（每段单独验收）

1. **法条批注系统 + 专题板块切除**（本版核心）：选区右键批注/浮窗/星标 + 专题代码与数据整链路移除；
2. **笔记库 + 大纲编辑器 + 插入浮层 + 星标**（2026-10-17 定稿：键位原样对齐幕布（Tab/Shift-Tab 缩进、空行 Backspace 反缩进到底再合并）、节点**要折叠**、节点级备注**不做**、树拍平成行列表渲染（幕布同手法）、插入浮层只做「＋ 连加」；阅读侧只加「复制引用」右键项 + 引用节点「打开来源」逃生门；续读契约见 §3.5；参考过幕布 6.0.2 安装包代码（只读，其数据未动））；

4. ~~**AI 全局面板迁移**~~（已提前完成并两轮重定位：**全局通用问答 + 真·独立 BrowserWindow**（frame:false 自绘标题栏延续主窗风格、不设 alwaysOnTop、引用转发主窗打开），迁移016 放开 article_id 可空）；

## 10. 风险与未决

- 大纲编辑器自研是最大工程件，第 2 段动工前先出交互原型稿；
- jsMind 视觉风格与全局 Apple 风需一次调色对稿；
- 批注星标的视觉形态（选区着色方案、★ 位置）实施前出对稿图；
- 书籍/资料/PDF 阅读面长期维持现状，后续版本再议是否统一；
- 专题数据删除为**不可逆**操作，删除迁移上线前需一次数据包备份提醒（用户已确认接受删除）。
