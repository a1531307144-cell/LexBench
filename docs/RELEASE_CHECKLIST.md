# LexBench 发布前安全审批清单

**适用时机**：每次 push 到 GitHub、打版本 tag、发布 Release 之前。
**原则**：自动扫描 + 人工复核，两关全部通过才允许发布。任何一关不通过 = 不发布。

> 本软件是开源项目，一旦推送到 GitHub，历史提交中的内容将永久公开。
> 宁可发布前多花十分钟，不要事后追溯泄露。

---

## 第一关：自动扫描（必须全绿）

```bash
python scripts/security_check.py --history --strict
```

- 退出码 `0` → 通过，进入第二关
- 退出码 `1` → 逐条修复后重扫
- 确认属于误报（如合成的测试样例）→ 在 `scripts/security_check.py` 配置区白名单登记，并在下方发布记录中注明

扫描覆盖：API key / 各类令牌 / 私钥、硬编码凭据赋值、含用户名的本机路径、
手机号、身份证号、邮箱、禁止入库的文件类型（data/、*.db、密钥、法律文档原件）、
git 全部提交历史。

CI（GitHub Actions）在每次推送与 PR 时自动运行同样的扫描作为第二道保险；
本地漏掉的会在 CI 上红灯拦截。

## 第二关：人工复核（逐项打勾）

- [ ] `git log -p <上个tag>..HEAD` 通读新增代码：无硬编码密钥、无个人真实信息
- [ ] 新增依赖来源可靠：`pip audit` / `npm audit` 无高危项
- [ ] `git ls-files` 复查：`data/`、`.env`、`*.db`、密钥文件、法律文档原件均未入库
- [ ] 文档 / README / 注释中无真实姓名、手机号、个人邮箱、身份证号
- [ ] 测试中的"个人数据"均为虚构样例，绝非真实案件当事人信息
- [ ] 所有密钥类配置一律走环境变量或界面输入（AI API key 等），代码中零硬编码
- [ ] 用户上传的法律文档、笔记、数据库只存于本地 `data/`，任何新功能不得改变这一点
- [ ] CHANGELOG 已更新，版本号符合语义化版本（semver）

## 红线（任何一条触发即终止发布）

1. 自动扫描存在未处置的错误
2. 提交历史中出现真实法律文档内容（版权 + 当事人隐私双重风险）
3. 任何形态的 API key / 密钥 / 私钥出现在提交中
4. 新功能将用户数据发送到本地服务之外的任何地方（AI 调用除外，且须用户主动配置）
